# Review: implementation vs plan, and vs the live UT journal browser

Date: 2026-10-22. HEAD at review: `5271f17` (note: the working tree was being edited by a
concurrent session while this review ran; see "Concurrent session" at the end).
Method: full read of `docs/plan.md`, `docs/scope.md`, `docs/decisions.md`,
`docs/plan-pure-openaire-crossref.md` as the binding spec, then code-level audit of
`backend/` and `frontend/` (two parallel read-only audits plus direct verification of
every finding quoted here), live API probing of the running compose stack, and a
side-by-side comparison with https://library.wur.nl/WebQuery/utbrowser.
Every finding below was verified against code or a live response; nothing is copied
from docs claims.

## Verdict

The build is substantially complete and honest: all ten phases exist, run, and match
their acceptance claims where spot-checked (Water Research enrichment, Pure-canonical
stats, deal register, curation flow, screenshot set). The stack is healthy right now.
The serious problems are reproducibility and refresh-path issues that the demo
happens to mask: a fresh install silently loses every Twente-scoped feature, a JCT
re-run would corrupt hand-curated deals, CI proves almost nothing (database tests
silently skip), and deal-coverage semantics disagree between the search facet, the
deals listing, and the journal panel for 757 journals.

## Findings

### Blocker

**B1. A fresh install silently loses every Twente-scoped feature.**
`get_home_institution` (`harvest/common.py:161-170`) and the OpenAlex journal
harvester (`harvest/openalex_journals.py:54`) set `is_home=True` only when they
create the institution row. The README run order starts with `ingest_jct`, which
creates the Twente row with `is_home=false` (server default; `test_jct.py:143`
asserts exactly that). Nothing ever updates an existing row, so `HOME_INST` resolves
to nothing: deal facet, `twente_works`, journal detail deals/stats, reconcile
tiering, and `apply_curation_2026_10_22.py` (`.scalar_one()` on `is_home`) all fail
or return empty. The current demo is unaffected only because the row was fixed by
hand. Phase 7's adopter story ("another university sets these two values") is broken
as shipped. Fix: set `is_home=True` on the ROR-matched existing row in both
resolvers, plus one regression test.

### Major

**M1. Deal coverage is inconsistent across search, deals listing, and journal
panels, for 6 current deals and 757 journals.**
Search's `DEAL_COVERED` (`services/search.py:12-22`) requires a home
`deal_institutions` row. The journal detail panel (`routers/journals.py:159-176`)
accepts any current canonical deal (`home row OR openaccess_nl_url IS NOT NULL`).
The deals listing (`routers/deals.py:51-57`, changed in `5271f17`) shows only
Twente-linked deals. Verified end to end: journal `T'oung Pao` (0082-5433, deal
`dgb2026ukb`, De Gruyter Brill) returns `deal_covered: false` in search while its
detail page lists the current DGB deal, and the deal is hidden from the home deals
listing. That contradicts decision 13's rule that a canonical current Twente deal is
never hidden, only badged "curation pending". Resolution is a product call: either
link the remaining 6 register-only deals (badge stays), or judge them non-Twente and
align the journal panel with the strict register. In all cases search, listing, and
panel must agree.

**M2. A JCT re-ingest corrupts hand-curated canonical deals.**
`jct.py::_store_agreement` upserts on `esac_id` and overwrites provenance, status,
and journal rows of an already-merged deal. The Emerald repair
(`jobs/ingest_emerald_contract.py`, which comments that a JCT re-run "must not
overwrite") has no enforcement; reconcile's shadow cleanup only handles unmerged
rows. Next scheduled refresh undoes the Emerald fix and pollutes other merged deals.
Fix: skip or merge-nothing when the esac_id belongs to a deal with
`openaccess_nl_url`, and record the conflict per decision 13.

**M3. CI runs zero database tests.**
`tests/conftest.py:13` probes database `journalbrowser`; the CI Postgres service
creates `journalbrowser_test` (`ci.yml:20,29`) and never sets `JB_TEST_DB`. All
`requires_db` tests skip silently, so green CI says nothing about the ~12 DB-backed
test files. Fix: create `journalbrowser` in CI or point `ADMIN_URL` at the service DB.

**M4. The quality bar admits 78% of the corpus, far outside the decision-12 estimate.**
Default scope is 138,897 of 177,181 (verified live), against the expected 50-70k
band, and 3.6x the live tool's ~49k. The predicate is implemented exactly as
decision 12 wrote it; the miss is the spec's estimate. `is_active_recently` passes
any journal with a single work since 2020, so OpenAlex's long tail dominates topic
facets (top topics are 3-5k-journal long-tail categories). Decision needed: tighten
the activity rule (minimum works in window, or recency threshold) or accept and
document the broad corpus.

**M5. `twente_works` means different things in the list and on the detail page.**
Search sums both stat sources per journal (`services/search.py:25-33`): Water
Research shows 45 (22 pure_canon + 23 openalex), double-counting works present in
both. The detail page applies the pure_canon-primary merge and shows 22. The list
column therefore overstates the headline number and contradicts the phase-10 rule
that Pure is primary with OpenAlex as a labeled cross-check. Fix: apply the same
merge in search.

**M6. The journal page drops caveats and the OpenAlex cross-check.**
`Attribution.caveat_codes` (`schemas.py:10`) never reaches `<SourceNote>`; all seven
journal-page call sites spread the attribution object and the component reads a
`codes` prop (`components/source-note.tsx:19`), so caveat hints silently vanish on
the most caveat-dense page. Separately, the phase-10 requirement that the OpenAlex
institution-filter count stay visible as a cross-check is not met; only a merged
series with a sometimes-misleading source label is shown
(`app/journals/[issn_l]/page.tsx:186-202`). Both violate scope.md's "every displayed
number carries its source and its registered caveats".

**M7. The OpenAlex seed route bypasses the landing store, and `--seed-deals-only` crashes.**
`seed_deal_journals` (`harvest/openalex_journals.py:125-143`) upserts without
`ingest_record`, so the 19,582 seeded sources leave no raw payload unless the later
sweep covers them; the module docstring claims otherwise. The job flag
`--seed-deals-only` (`jobs/harvest_journals.py:37`) passes a `None` client and
raises `AttributeError`. Both violate the "local copies always" constraint.

**M8. No tests cover the phases 2/3/8/9 machinery.**
Nothing tests `harvest/pure.py`, `harvest/enrich.py` (the ladder behind the 78.2%
claim), `harvest/openaire.py`, `harvest/institution_stats.py`,
`harvest/openalex_journals.py` flag computation, `harvest/scimagojr.py` (the parser
docs warn about), keyset pagination, FTS search, or the detail bundle. The suite's
73 passing tests cover maybe a third of the harvest surface.

**M9. The 2020 window is not enforced in OpenAPC normalization.**
`build_aggregates`/`build_evidence` (`harvest/openapc.py:96-176`) accept any period;
upstream CSVs contain pre-2020 rows. Current data appears in-window, but nothing
guarantees it. Fix: filter `period >= 2020` in both builders.

**M10. The ut-metadata verification gate is weaker than the plan.**
`verify_utmetadata.py` counts retired works (no `retired_at IS NULL` filter) and
allows up to 5 unexplained rows in the top-20 gate, while phase 10 acceptance says
"zero unexplained rows". The published acceptance is therefore looser than specced.

**M11. Landing-zone durability depends on where a job ran.**
The compose backend has no volume for `landing/`; the curation report exists only
inside the container (`landing/reports/` on the host is empty) despite plan.md and
decisions.md calling it live at that path. A container rebuild discards any raw
payloads or reports written in-container, against the "local copies always"
constraint. Also, `landing/` root is littered with harvest `.log` files. Fix: mount
`./backend/landing` into the container, regenerate the report on the host path, move
logs out of the landing tree.

### Minor

- Journal detail returns `in_scimago: false, last_active_year: null` while the DB row
  says true/2026: `journal_detail` builds `JournalListItem` without those two fields
  (`routers/journals.py:263-274`, defaults at `schemas.py:23-24`). UI does not render
  them yet, so this is a latent API-contract bug.
- openaccess.nl re-scrape overwrites `needs_curation`/reason, wiping reconcile and
  contract-reconstruction flags until those jobs re-run (`harvest/openaccess_nl.py:307,336-341`).
- The home deals register depends on a one-off curation job; a fresh scrape+jct+reconcile
  run reproduces the M1 divergence for register-only deals.
- Title-sort keyset compares the raw title column while ordering by
  `lower(title)`; case edges can skip or repeat rows (`services/search.py:161-164,195-206`).
- ISSN search matches only `issn_l`; a print/online ISSN that differs finds nothing,
  and the purpose-built `issn_map` is unused in search (`services/search.py:130-140`).
- Facet counts apply the facet's own oa/doaj/quartile filter, contradicting the
  docstring's "own filter excluded" contract (`services/search.py:242-275`).
- Local suite is flaky: 2 of 75 tests errored on a function-scoped drop/create race
  on the shared pytest database (`tests/conftest.py:26-47`).
- SourceNote tooltips are hover/focus CSS only, no `aria-describedby`; caveat content
  is invisible to screen readers (`components/source-note.tsx:33-44`).
- Search page keeps the pagination cursor out of URL state and resets it in an
  effect, so one fetch can race with a filter change (`app/page.tsx:64-71`).
- Active topic facet renders a false count of 0 when forced into the top-8 slice
  (`app/page.tsx:103-104`); unused `Badge` import (`app/page.tsx:16`); "Deal coverage"
  chip label duplicates the facet group name; `next.config.mjs` comment names a
  nonexistent `NEXT_PUBLIC_API_URL` (actual: `API_PROXY_URL`).
- `pg_trgm.similarity_threshold` set session-scoped leaks across pooled requests
  (`harvest/openaire.py:196-199`; use transaction-local).
- `JB_OPENAIRE_ORG_ID` is documented as configurable but `config.py` never defines
  the setting, so other-university OpenAIRE harvests would still use Twente's org id.
- `backfill_flags.py` can only move `last_active_year` forward; journals that lost all
  recent works keep stale `is_active_recently=true`.
- The freshness endpoint serves scimago/openapc years as if they were timestamps
  (`routers/meta.py:53-64`); the About page will print "2024" as a date.
- The limitations registry has no entries for the phase 8-10 sources (Pure, OpenAIRE,
  Crossref), so the pure_canon vs OpenAlex difference ships without a registered caveat.
- `apc_evidence` is Twente-only; plan phase 1 says Twente and NL peers.
- Dead weight: `journals.crossref_meta`/`openaire_meta` never written;
  `harvest/institution_aliases.py` orphaned; `DATA_WINDOW_START` unused; `loguru`
  dependency unused; `reconcile.py` declares `actions` twice; dead `if True` in
  `ingest_emerald_contract.py:246`; `routers/journals.py:199-205` mutates ORM objects
  on GET (safe only because the session never commits).
- `test_health.py` accepts 200, 500, or an exception; effectively unasserted.
- README status section is stale (claims phases 7-10 pending; they are done).
