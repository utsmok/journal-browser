# Implementation plan

Stack: FastAPI + SQLAlchemy 2 (async) + PostgreSQL 17 backend, Next.js (App Router,
TypeScript) frontend, Docker Compose, `uv` for Python. OpenAlex access via an async client
built on `bibliofabric` (pattern: `stavrophora`), ingestion jobs as plain `uv run` scripts
(`backend/jobs/`).

## Phase 0 — Foundations (skeleton in repo already)

- [x] Repo layout, docker-compose (db/backend/frontend), FastAPI `/api/v1/healthz`,
      Next.js skeleton, `.env.example`, docs tree.
- [ ] Alembic migrations wired; CI (ruff + pytest + frontend build).
- [ ] OpenAlex client library (`backend/src/journal_browser/openalex/`): sources + works
      resources, cursor iteration, batched OR-filters (≤100 IDs), API-key auth, TTL cache,
      Retry-After backoff. Modeled on `stavrophora`; queries per `docs/research/openalex.md`.

## Phase 1 — Deal data model + ingestion (the core)

Data model (Postgres):

- `publishers` (name, openalex host_organization id, openaccess.nl slug)
- `institutions` (name, ROR, openalex I-id, our-institution flag)
- `deals` (publisher_id, esac_id, status current/archive, start/end dates,
  corresponding-authors-only, summary, conditions_text, workflow_text, cap text +
  per-year cap numbers, contract_url, openaccess_nl_url, per-year OA counts jsonb,
  provenance fields, last_reviewed)
- `deal_journals` (deal_id, issn_l, first/last seen, source: jct|manual)
- `deal_institutions` (deal_id, institution_id, first/last seen)
- `manual_overrides` (table+field, value, rationale, set-by, set-at) — curation layer
  that re-ingestion never overwrites.

Jobs:

1. `ingest_jct`: fetch TA index CSV → per-agreement Data CSVs → upsert deals,
   deal_journals (ISSN→ISSN-L normalization), deal_institutions (ROR→our institutions).
2. `scrape_openaccess_nl`: overview → publisher pages → deal pages; store raw HTML in
   landing table + parsed structured fields; diff report on changed texts.
3. `reconcile`: match openaccess.nl deals ↔ JCT deals (publisher × duration); emit
   curation report of unmatched/conflicting rows (e.g. ACM local deals, non-Plan-S deals).

Acceptance: for each of the ~22 current openaccess.nl deals, the DB shows a deal record
with journal list (or an explicit "needs curation" flag), institutions, cap info, and
source links. Verified against 5 known deals (Karger, Elsevier, OUP, PLOS, Thieme).

## Phase 2 — Journal backbone (OpenAlex)

- `journals` table: openalex source id, issn_l, issns, title, publisher, type, is_oa,
  is_in_doaj, homepage, topics (jsonb), apc_prices, summary_stats, counts_by_year,
  raw landing payload. Refresh job: `sources` cursor sweep + targeted updates for
  deal-covered ISSNs.
- `institution_works_stats` per journal×year: works count, OA-status counts, computed
  from `works?filter=institutions.id:I…,primary_location.source.id:S…&group_by=…`
  (and one full-institution sweep per year for trends).
- `journal_citations` ("cited by our staff"): two-step W-id batching per
  openalex.md §4, refreshed quarterly, bounded to a 5-year window.
- Scimagojr ingest: SJR + quartile per ISSN-L (yearly CSV).

Acceptance: sample journals (Water Research, PLOS ONE, NJAS-Wageningen Journal of Life
Sciences) show stats matching live OpenAlex queries.

## Phase 3 — Search API

`/api/v1/journals` — query (title/ISSN), facets: deal_coverage, is_oa, is_in_doaj,
topic, quartile; sorts: relevance, title, institution works, 2yr_mean_citedness;
pagination. Postgres FTS on title + alternate titles, facets via filtered count queries.
`/api/v1/journals/{issn_l}` — full detail bundle. `/api/v1/deals`,
`/api/v1/deals/{id}` — deal records with journal counts. OpenAPI auto-documented.

## Phase 4 — Frontend

- Home: search bar + facet chips + results list (title, publisher, deal badge, OA flag,
  our-works count).
- Journal page: deal panel (cost implication for *our* authors, cap status, article
  types, workflow summary, links to openaccess.nl + contract PDF), stats (per-year bars,
  OA split), metrics card, topics, similar journals.
- Deals page: browse current deals, the openaccess.nl narrative rendered structured.
- About: data sources + update cadence + disclaimers.

## Phase 5 — Curation & ops

- Staff-facing curation report (unmatched deals, stale data, scraper diffs) — read-only
  HTML generated by the reconcile job (no auth system needed for v1).
- Scheduled jobs (compose service or cron) + freshness metadata per table surfaced in
  the About page and API (`/api/v1/meta/freshness`).

## Risks & mitigations

- **openaccess.nl drift** (prose changes, new deals): scraper diffs + curation report;
  manual overrides survive re-runs.
- **OpenAlex API quirks/regressions** (observed: mailto deprecation, source-filter
  changes): quirks doc in the client repo, live-marker tests.
- **Deal lists not in JCT** (local deals, non-Plan-S): explicit curation queue, honest
  "unknown" in UI — never guess coverage.
- **Metric expectations** (users want CiteScore/SJR): label open metrics clearly; scimagojr
  covers SJR/quartile; CiteScore-lookalike derived from counts_by_year where feasible.
